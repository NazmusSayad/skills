---
name: documentation
description: Guides documentation for the right audience. Use when creating, updating, reviewing, or restructuring documentation, README files, guides, tutorials, or references.
---

Identify what the audience needs to understand or accomplish, and write at their level. Include only the context, terminology, technical depth, and examples they need. Include implementation details only when they help achieve that goal. Ask the user only when the audience cannot be determined.

Ground documentation in implemented behavior, authoritative project sources, existing documentation, and local conventions. Verify discrepancies between sources. When creating or updating documentation, match surrounding structure and terminology, and keep the change within scope.

Lead with the reader's needed outcome or information, then explain why when useful. Use direct language, clear headings, and the smallest useful accurate examples.

Keep documentation compact and canonical. Link to the authoritative detail rather than duplicating it, while retaining the context readers need to use the document independently.

Verify claims, commands, examples, and links. When reviewing, report only new issues that materially affect accuracy, clarity, or the audience's success.
